# Skill: write-portfolio

## 목적

경험 DB 중 프로젝트형 경험을 골라 포트폴리오 **목차와 각 장 텍스트 초안**을 만든다.

> **범위를 의도적으로 좁힌다** (ROADMAP S7-2). 완성된 디자인 산출물(레이아웃, 이미지,
> PDF 조판)은 전혀 다른 문제다. 여기서 만드는 것은 목차 구성과, 각 장에 들어갈 본문
> 텍스트 초안까지다. 디자인은 사용자가 이 초안을 가지고 직접 만든다.

## 트리거

"[이름] [기업명] [직무명] 포트폴리오 써줘" 또는 공고 없이 "[이름] 포트폴리오 초안 만들어줘"

## 절대 원칙

1. **경험을 지어내거나 과장하지 않는다** (Claude.md 공통 원칙). 경험 파일에 없는 성과,
   수치, 역할을 새로 만들지 않는다.
2. **각 장 끝에 "참조한 경험: [파일명]"을 반드시 명시한다** (Claude.md 의 자소서 규칙과
   같은 정신 — 포트폴리오도 근거 없이 쓰지 않는다). 실재하지 않는 파일명을 인용하지 않는다.
3. 공고가 주어졌다면(필수/우대조건이 있다면) 그 조건과 관련 있는 프로젝트를 우선한다.
   공고가 없으면 관심직무.md 의 핵심 키워드와 관련 있는 프로젝트를 우선한다.
4. 성과/수치는 경험 파일에 실제로 쓰여 있는 것만 인용한다. 없는 수치를 "약 N%" 식으로
   지어내지 않는다 — 수치가 없으면 정성적 설명만 쓴다.

## 실행 순서

### 1. 프로젝트형 경험 선정 (보통 2~4개)

- 카테고리가 "전문성·직무역량"이거나, 구체적 산출물·정량적 성과가 있는 경험을 우선한다
- 공고 필수/우대조건과 연결되는 경험을 최우선으로 한다(조건 대응 근거는 이미 매칭
  결과로 주어질 수 있다 — 그 경우 스킬은 선정을 새로 하지 않고 주어진 경험 목록만 쓴다)
- 같은 프로젝트를 두 번 다른 장으로 쪼개지 않는다

### 2. 목차 구성

도입(역량 요약, 1장) + 프로젝트별 장(각 1개) + 필요하면 마무리(배운 점 종합) 순서로
목차를 구성한다.

### 3. 장별 텍스트 초안 작성

각 프로젝트 장은 아래 구조로 쓴다:

- **프로젝트 개요**: 무엇을 왜 했는지 한두 문장
- **문제/배경**: 어떤 상황이었는지 (경험 파일의 Situation 참고)
- **내가 한 일**: 구체적으로 무엇을 했는지 (경험 파일의 Action 참고, 다른 사람이 한 것과
  구분해서)
- **결과/성과**: 경험 파일의 Result 를 재료로, 있는 수치와 사실만 서술
- **배운 것**: 경험 파일의 "배운 것 / 느낀 것" 참고

문장은 새로 쓰되(포트폴리오 톤에 맞게 다듬음), 사실 관계와 수치는 경험 파일에 있는
그대로만 쓴다. 사용자의 writing-style.md 어투를 참고하되, 포트폴리오는 자소서보다
간결하고 항목 나열식이어도 된다.

각 장 마지막 줄에:

```text
참조한 경험: [파일명]
```

### 4. 출력

```text
===TOC===
1. 도입 — [한 줄 요약]
2. [프로젝트명]
3. [프로젝트명]
...
===END===

===CHAPTER: 1===
(도입 텍스트 — 경험 인용 없음, 참조한 경험 줄 없음)
===END===

===CHAPTER: 2===
(장 텍스트)

참조한 경험: [파일명]
===END===
```

TOC 의 챕터 번호와 CHAPTER 블록 번호가 정확히 일치해야 한다.

## 절대 금지

- 경험에 없는 성과, 수치, 역할을 새로 만드는 것
- 실재하지 않는 경험 파일명을 "참조한 경험"으로 인용하는 것
- 완성된 디자인/레이아웃까지 만들려는 것 (이 스킬의 범위 밖)
- 도입/마무리 장에 특정 경험을 인용하면서 "참조한 경험" 표시를 빠뜨리는 것
