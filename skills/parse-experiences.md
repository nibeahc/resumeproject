# Skill: parse-experiences

## 목적

users/[이름]/raw/ 안의 자소서 원본 파일을 읽고
구조화된 경험 파일과 어투 분석 파일을 자동 생성한다

## 트리거

"[이름] 파싱해줘" 또는 "[이름] 자소서 정리해줘"

## 실행 순서

### 0-A. 신규 raw 파일 감지 (재파싱 분기)

파싱 시작 전 아래 비교를 수행한다.

1. `users/[이름]/experiences/` 파일 목록 확인 (이미 파싱된 경험들)
2. `users/[이름]/raw/apply/` 및 `raw/logs/` 파일 목록 확인

**experiences/ 파일이 1개 이상 존재하는 경우 (이미 파싱된 적 있는 사용자):**

- 각 raw 파일명을 experiences/ 파일명과 비교하여 아직 파싱되지 않은 신규 raw 파일을 찾는다
- 신규 raw 파일이 없으면 → "신규 파일이 없습니다. 전체 재파싱합니까?" 질문 후 확인 받고 진행
- 신규 raw 파일이 있으면 → 아래와 같이 질문한다:

  ```text
  신규 파일 [N]개가 감지되었습니다:
  - [파일명1]
  - [파일명2]

  신규 파일만 추가 파싱합니까, 아니면 전체를 재파싱합니까?
  1. 신규 파일만 추가 파싱 (기존 experiences/ 보존)
  2. 전체 재파싱
  ```

  - "신규 파일만" 선택 시 → 해당 파일만 0-B 단계부터 파싱, 기존 experiences/ 파일은 건드리지 않음
  - "전체 재파싱" 선택 시 → 전체 진행

**experiences/ 파일이 없는 경우 (최초 파싱):** 바로 0-B 단계로 진행

### 0-B. 읽을 수 없는 파일 변환 (전처리)

파일 확장자에 따라 아래 방법으로 텍스트를 추출한 뒤 파싱을 진행한다.

#### HWPX (.hwpx)

HWPX는 ZIP 구조이므로 Python으로 XML에서 텍스트를 추출한다.

```python
import zipfile, re

def extract_hwpx(filepath):
    with zipfile.ZipFile(filepath, 'r') as z:
        xml = z.read('Contents/section0.xml').decode('utf-8')
    texts = re.findall(r'<hp:t[^>]*>([^<]+)</hp:t>', xml)
    return '\n'.join(texts)
```

#### HWP (.hwp, 구버전)

pyhwp 라이브러리의 hwp5txt 명령어를 사용한다.

- 설치 경로: `/Users/chaebin/Library/Python/3.9/bin/hwp5txt`
- 추출된 텍스트가 100자 미만이면 내용이 없거나 암호화된 파일로 간주하고 스킵한다.

```bash
/Users/chaebin/Library/Python/3.9/bin/hwp5txt [파일경로]
```

#### DOCX (.docx)

python-docx 또는 unzip 후 word/document.xml 파싱으로 추출한다.

```python
import zipfile, re

def extract_docx(filepath):
    with zipfile.ZipFile(filepath, 'r') as z:
        xml = z.read('word/document.xml').decode('utf-8')
    texts = re.findall(r'<w:t[^>]*>([^<]+)</w:t>', xml)
    return '\n'.join(texts)
```

### 1. raw/ 파일 읽기

raw/ 하위에는 두 종류의 폴더가 있다:

- `raw/apply/` : 자소서, 지원서, 이력서, 신청서, 포트폴리오 등 지원/신청을 위해 작성한 문서
- `raw/logs/` : 활동일지, 소감문, 결과보고서, 포토에세이 등 활동 중 작성한 기록 문서

**폴더가 없는 경우 (아직 분류 전):**

- raw/ 루트에 있는 파일들을 파일명 기준으로 아래와 같이 분류한다
  - apply: 자기소개서, 지원서, 신청서, 이력, 포트폴리오, portfolio 포함 파일명
  - logs: 소감문, 활동일지, 결과보고서, 포토에세이, 주간활동 포함 파일명
- 분류 결과를 사용자에게 보여주고 확인받은 후 apply/, logs/ 폴더로 이동한다
- 판단이 어려운 파일은 사용자에게 직접 물어본다

각 폴더의 모든 파일에 대해 0-B 단계 방법으로 텍스트를 추출한다.
파일이 없으면 "raw/ 폴더에 자소서 파일이 없습니다" 출력 후 중단

- (writing-style.md 의 "피해야 할 표현" 각 항목을 그대로 옮긴다. 그 섹션이 비어 있으면
  "(분석된 것 없음 — raw/ 원문에서 발견되지 않음)" 한 줄만 남긴다)

## 선호 표현

- (writing-style.md 의 "특유 표현·선호 어휘" 중 상위 2~3개를 옮긴다)

- (자유롭게 추가)

**파일 우선순위:** 파일명 또는 내용에서 날짜를 파악하여 가장 최근 서류/자기소개서/지원서의 어투를 더 높은 가중치로 반영한다. 오래된 파일은 참고 수준으로만 사용한다.

**어투/문체 분석:**

- 문장 길이 경향 (짧고 간결 / 길고 서술적)
- 자주 쓰는 문장 시작 방식
- 자주 쓰는 어미 (예: ~했습니다 / ~했어요 / ~했다)
- 자주 쓰는 표현이나 단어
- 전반적인 톤 (감성적 / 논리적 / 경험 중심 등)
- 특징적인 문체 습관
- 피해야 할 표현 (본인 스타일과 어긋나는 클리셰, 막연한 다짐, 수동적 서술 등 — raw/ 원문에 실제로
  나타나지 않는 항목은 억지로 만들지 말고 생략한다. 이 섹션은 아래 writing-rules.md 초안이
  참조하므로 반드시 독립된 "## 피해야 할 표현" 섹션으로 작성한다)

**의미화 패턴 분석 (경험을 어떻게 서사화하는가):**

- 사고방식: 문제를 만났을 때 어떤 방식으로 접근하고 해석하는가 (원인 분석 / 즉각 실행 / 타인 관찰 등)
- 감정 표현 방식: 감정을 직접 드러내는가 / 행동으로 우회하는가 / 거의 드러내지 않는가
- 성장 서사 구조: 경험의 끝을 어떻게 마무리하는가 (깨달음 → 변화 / 결과 → 다짐 / 과정 강조 등)
- 타인과의 관계 묘사 방식: 팀을 어떻게 언급하는가 (내가 이끈 / 함께 한 / 지지받은 등)
- 자기 평가 방식: 자신을 어떻게 규정하는가 (강점 중심 / 성장 중심 / 역할 중심 등)

### 2-B. profile.md 가치관 업데이트

`raw/apply/` 파일 전체를 읽고 아래 항목을 분석하여 `users/[이름]/profile.md` 의 **가치관·핵심 강점 섹션**을 업데이트한다.

**분석 항목:**

1. **본인이 직접 쓴 키워드** — 자소서에서 자신을 설명할 때 명시적으로 사용한 단어·표현. 원문 그대로 보존.
2. **글에서 반복되는 행동 패턴** — 여러 자소서에 걸쳐 동일한 상황 대처 방식이 반복되면 패턴으로 기록.
3. **가치관 원문 발췌** — 자소서·소감문에서 가치관을 직접 서술한 문장을 발췌해 출처 파일명과 함께 기록.
4. **감사·겸손 등 태도적 특성** — 글의 마무리 방식이나 반복되는 태도 표현에서 추출.

**업데이트 방식:**

- 기존 내용을 삭제하지 않고, 새로 발견된 내용을 추가하거나 기존 서술을 더 풍부하게 보완한다.
- 자소서 원문 인용 시 큰따옴표("") 사용 + 출처 파일명 표기.
- 추론이나 과장 없이 실제 문장에서만 추출한다.

**업데이트 대상 섹션:**

- `## 핵심 강점` — 본인이 직접 쓴 키워드와 설명 보완
- `## 자소서 글에서 드러나는 추가 패턴` — 없으면 새로 생성
- `## 가치관` — 원문 발췌 + 출처 추가

### 3. 경험 목록 추출 (오래된 경험 처리 + 중복 처리 + STAR 품질 점검)

`raw/apply/` 와 `raw/logs/` 모두에서 등장하는 모든 경험을 추출한다
(어투는 apply만 참고하되, 경험 내용은 양쪽 모두 참고하여 더 풍부하게 구성한다)

#### 오래된 경험 처리 (일괄 확인)

경험을 추출하는 과정에서 아래 기준에 해당하는 경험이 발견되면 파싱 완료 후 **일괄 질문**한다.

**기준 (하나라도 해당하면 질문 목록에 추가):**

- 현재 연도 기준 5년 이상 전 경험
- 대학교 입학 이전의 경험 (고등학교, 중학교 시절 등)

**파싱 완료 후 일괄 질문 형식:**

```text
아래 경험들은 오래되었거나 대학 입학 이전의 경험입니다.
포함할 경험에 번호를 알려주세요. (예: 1, 3)
포함하지 않을 경험은 건너뜁니다.

1. [YYYY] [활동명] — [기관명]
2. [YYYY] [활동명] — [기관명]
```

- 포함 선택 시 → 경험 파일 생성
- 미선택 시 → 스킵 (파싱 결과 보고에 "제외됨" 표시)

#### 중복 판단 기준

아래 중 2개 이상 겹치면 같은 경험으로 판단한다

- 활동명 또는 기관명이 동일하거나 유사
- 시기가 겹침
- 핵심 에피소드(사건)가 동일

#### 중복 처리 방법

같은 경험으로 판단된 경우

- 파일은 하나만 생성한다
- 여러 자소서에 걸쳐 나온 표현 중 가장 구체적이고 풍부한 내용을 선택한다
- STAR 각 항목별로 가장 잘 서술된 버전을 골라 합친다
- "이 경험으로 쓸 수 있는 문항 유형" 은 모든 버전에서 나온 것을 합산한다

#### 중복 판단이 애매한 경우

- 일단 별도 파일로 생성한다
- 파일 하단에 "⚠️ 확인 필요: [파일명]과 유사한 경험일 수 있음" 을 표시한다

#### STAR 품질 점검

각 경험을 추출할 때 아래 기준으로 누락 여부를 판단한다.

- Result에 수치(%, 건수, 기간, 점수 등)가 전혀 없는 경우
- Result가 "좋은 결과를 얻었다" 등 추상적 서술에만 그치는 경우
- Action이 "열심히 했다" 수준의 단일 문장인 경우

위 중 하나라도 해당하면 경험 파일 하단에 아래 표시를 추가한다:

> ⚠️ STAR 보강 필요: Result에 수치/구체적 사실이 부족합니다. 실제 수치나 구체적 변화를 보충하세요.

Action만 추상적인 경우(Result는 정상)는 별도 표시를 추가한다:

> ⚠️ STAR 보강 필요: Action이 구체적이지 않습니다. 내가 직접 한 행동을 단계별로 보충하세요.

이 플래그는 7단계 완료 보고의 "확인 필요 항목"에 "STAR 보강 필요: [경험명]"으로 집계한다.

### 5. 관심직무.md 처리

users/[이름]/관심직무.md 를 확인한다

**파일이 있고 내용이 있으면:** 그대로 둔다 (건드리지 않음)

**파일이 없거나 비어있으면:**

- raw/ 및 생성된 경험 파일에서 지원 이력, 직무 언급, 목표 서술 등을 분석해 관심직무를 추론한다
- 추론된 직무 목록과 각 직무별 핵심 키워드를 제안한다
- 사용자에게 확인받은 후 관심직무.md 를 생성한다

**직무별 핵심 키워드 작성 원칙:**

- 키워드는 반드시 해당 사용자의 경험 DB(index.md 키워드별 항목)에 실제로 존재하는 것만 사용한다
- 배경지식이나 직무 특성에서 임의로 키워드를 추가하지 않는다
- 사용자가 직접 입력한 키워드도 그대로 유지한다
