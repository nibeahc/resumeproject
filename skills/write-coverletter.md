# Skill: write-coverletter

## 목적

자소서 문항과 글자수를 입력받아
기업 정보·직무 톤·합격 사례를 자동으로 참조하고
해당 사용자의 어투와 경험을 바탕으로 문단을 작성한다

## 트리거

`"[이름] [기업명] [직무명] 자소서 써줘: [문항] / [글자수]"`

- 기업명·직무명이 없으면 먼저 물어본다
- 글자수가 없으면 먼저 물어본다

## 글자수 규칙

- 글자수가 주어지지 않으면 작성 전에 반드시 먼저 물어본다
- 띄어쓰기 포함/제외를 명시하지 않으면 **기본값은 띄어쓰기 포함**으로 처리한다
- 글자수 초과는 절대 금지. 출력 후 실제 글자수를 반드시 표기한다
- 글자수 제한이 주어지면 기준점에 최대한 가깝게 채운다 (여유 있게 짧게 쓰는 것 금지)

## 실행 순서

### Step 1. 사용자 데이터 로드

- `users/[이름]/writing-style.md` 읽기
- `users/[이름]/writing-rules.md` 읽기 (충돌 시 writing-style.md 보다 우선 — `Claude.md` "규칙 우선순위")
- `users/[이름]/index.md` 읽기
- `users/[이름]/관심직무.md` 읽기
- `users/[이름]/glossary.md` 읽기 — 외부 독자가 모르는 고유명사를 어떻게 쓸지. 기준은 "영어인가" 가 아니라 "지원서를 읽는 담당자가 이 이름을 알 수 있는가" 다 (한국어 소모임명도 해당한다)

### Step 2. 기업 정보 수집 (자동)

`companies/[기업명].md` 파일을 확인한다.

**파일이 있는 경우 → 캐시 사용:**

- 파일을 읽고 Step 3으로 진행
- 수집 일자가 90일 이상 지났으면 "정보가 오래되었습니다. 갱신합니까?" 질문

**파일이 없는 경우 → MCP로 자동 수집:**

MCP(Perplexity 또는 Brave Search)로 아래 항목을 검색한다:

1. `[기업명] 핵심 가치 미션 비전`
2. `[기업명] [직무명] 채용 공고 자격요건 우대사항`
3. `[기업명] 최근 뉴스` (실행일 기준 최근 12개월. 연도를 고정해 적지 않는다 — 한 번 적어두면 해가 바뀌어도 그대로 남는다)
4. `[기업명] CEO 대표 인터뷰 발언`

수집한 내용을 `templates/company-entry.md` 형식에 맞춰 `companies/[기업명].md`로 저장한 뒤 Step 3으로 진행

**수집에 실패한 경우 (MCP 미연결, 검색 결과 없음 등):**

**추론해서 채우지 않는다.** 학습 데이터에 있는 기업 정보는 시점이 불확실하고 검증할 수
없으며, 자소서에 들어가면 면접에서 그대로 질문받는다.

순서대로 시도한다:

1. `outputs/[이름]/[기업명]_culture.md` 가 있으면 읽어서 활용
2. 사용자에게 공식 자료를 요청한다:
   > "[기업명]에 대한 검증된 자료를 찾지 못했습니다. 채용 공고 전문, 기업 홈페이지 내용,
   > 또는 알고 계신 정보를 붙여넣어 주세요. (없으면 '없음')"
   - 답변이 있으면 `outputs/[이름]/[기업명]_culture.md` 로 저장하고 출처를 "사용자 제공" 으로 남긴다
3. 그래도 없으면 **사용자에게 명시적으로 동의를 구한다**:
   > "기업 정보 없이 작성하면 기업 고유의 사실(핵심가치, 뉴스, 인재상)을 한 줄도 쓸 수
   > 없습니다. 공고에 적힌 내용만으로 작성할까요?"
   - 동의하면 **열화 모드**로 진행한다. 기업 고유 사실을 일절 쓰지 않고, 공고 원문에
     적힌 내용만 근거로 삼는다. 초안에 "⚠️ 기업 정보 미조사" 를 명시한다
   - 동의하지 않으면 작성하지 않는다

> 웹 경로에서는 `web/routes/generate.py` 가 이 절차를 코드로 강제한다 (S11-1).
> `companies/[기업명].md` 가 없으면 생성을 멈추고 동의를 받는다.

### Step 3. 직무 톤앤매너 파악

`users/[이름]/관심직무.md` 에서 해당 직무의 정보를 읽는다:

- 핵심 키워드
- 추천 표현
- 피해야 할 표현
- 이 직무에서 강조할 경험 유형

직무명이 관심직무.md 에 없는 경우 → 기업 정보에서 직무 특성을 추론해서 사용

### Step 4. 합격 사례 레퍼런스 확인 (로컬 → MCP 자동 검색)

`references/coverletter/[직무명]/` 폴더를 먼저 확인한다.

**로컬 파일이 있는 경우:**

- 해당 파일들을 읽고 구조·전개 방식·강조 포인트를 학습
- Step 5로 진행

**로컬 파일이 없는 경우 → MCP로 자동 검색:**

Exa MCP (없으면 Perplexity MCP)로 아래 쿼리를 순서대로 검색한다:

1. `[기업명] [직무명] 자소서 합격 사례 후기`
2. `[직무명] 자기소개서 합격 예시`
3. `[직무명] 자소서 잘 쓰는 법 합격`

검색 결과에서 아래 기준으로 참고할 내용을 추출한다:

- 전개 방식 (두괄식/미괄식, 분량 배분)
- 강조한 역량 유형 (기술/태도/성과 중 무엇을 앞세우는지)
- 문장 구조 패턴 (STAR 구조 활용 방식)
- 해당 기업/직무에서 자주 등장하는 키워드

추출한 내용을 `references/coverletter/[직무명]/[기업명]_MCP수집_YYYY-MM-DD.md` 로 저장한다 (다음 번 캐시 활용).

**MCP도 연결되지 않은 경우:** 이 단계 스킵

---

**레퍼런스 참조 원칙 (반드시 준수):**

- 구조·전개 방식·강조 포인트만 참고
- 레퍼런스의 문장·표현·사례를 그대로 쓰는 것 절대 금지
- 표현과 사례는 반드시 해당 사용자의 실제 경험에서만 가져온다

### Step 5. 문항 분석

문항의 핵심 의도와 키워드를 파악한다

예:

- "갈등을 극복한 경험" → 키워드: 갈등, 극복, 팀워크
- "지원 동기" → 키워드: 가치관, 동기, 직무역량, 기업 핵심 가치와 연결
- "본인의 강점" → 키워드: 강점, 성격, 성과

### Step 6. 질문 유형 분류

문항을 아래 4가지 유형 중 하나로 분류한다.
유형에 따라 Step 7(경험 선택)에서 꺼낼 재료가 달라진다.

#### 유형 판단 기준

| 유형 | 신호 표현 (예시) | 핵심 질문 |
|------|----------------|----------|
| 경험형 | "경험을 말하시오", "사례를 들어", "극복한 경험", "발휘한 경험" | 무엇을 했는가 |
| 가치관형 | "본인의 가치관", "강점/약점", "어떤 사람인지" | 어떤 사람인가 |
| 지원동기형 | "지원한 이유", "왜 이 직무를", "입사 후 목표", "포부" | 왜 여기인가 |
| 성장형 | "성장한 경험", "배운 점", "실패에서 얻은 것", "변화한 것" | 무엇을 얻었는가 |

신호가 혼재하면 가장 강한 신호의 유형 하나로 결정한다.
판단 결과는 내부적으로만 사용하고 사용자에게 별도 출력하지 않는다.

#### 유형별 사용 재료

- **경험형** → experiences/ 파일 (STAR의 Action/Result 중심)
- **가치관형** → profile.md + experiences/ (카테고리 "가치관·동기" 우선)
- **지원동기형** → profile.md + 관심직무.md (포부/지원이유 섹션) + experiences/ (직무 관련 경험 보조)
- **성장형** → experiences/ 파일 ("배운 것 / 느낀 것" 섹션 중심)

### Step 7. 지원자-기업 매핑 후 경험 선택

> 웹 경로(web/routes/generate.py)에서는 이 단계를 `lib/selector.py` 가 코드로 미리 수행하고,
> 선택된 경험만 이 스킬에 전달한다 (ROADMAP S3-1). 그 경우 이 단계는 건너뛰고 Step 8로 바로 간다.
> 대화형으로 이 스킬을 직접 실행할 때(선택된 경험이 주어지지 않았을 때)는 아래 절차를 그대로 따른다.

index.md의 카테고리/키워드에서 문항과 관련된 경험을 찾는다.

**매핑 기준 (우선순위 순):**

1. 문항 키워드와 경험 키워드가 직접 겹치는 것
2. 기업 핵심 가치·채용 키워드와 연결되는 것
3. 해당 직무 유형에서 강조할 경험 유형

지원동기형은 관심직무.md의 포부/동기 내용을, 가치관형·성장형은 profile.md를 추가로 읽는다.

**경험 후보 확인 (문단 작성 전 반드시 거친다):**

매핑 기준으로 추린 후보 경험을 문단 작성(Step 8) 전에 먼저 사용자에게 제시하고 확인받는다.

- 후보 경험을 표로 제시한다: 활동명 / 핵심 키워드 1줄 요약
- "이 경험을 사용하시겠습니까?" 형식으로 확인을 받는다
- 사용자가 번호로 선택하거나 "전부 사용" 등으로 응답하면 그 경험(들)로 작성을 진행한다
- 사용자가 다른 경험을 지목하면 그 경험으로 교체한다

**오래된 경험 확인:**

선택한 경험 파일에 "⚠️ 오래된 경험" 태그가 있으면 위 확인 단계에서 함께 명시한다.

> "선택된 경험 '[경험명]'은 5년 이상 지난 경험입니다. 이 경험으로 작성할까요? (네 / 다른 경험으로)"

- 네 → 해당 경험으로 작성을 진행한다.
- 다른 경험으로 → 다음 후보 경험을 제안하고 다시 확인한다.

**경험 선택 원칙:**

- 활동은 **최대 2개, 기본 1개**만 사용한다
- 여러 활동을 나열하는 방식은 금지. 하나의 경험을 깊이 있게 풀어낸다
- 2개를 쓸 경우 두 경험이 자연스럽게 연결되어야 한다

  경험 파일 메타의 연도를 그대로 쓴다 (2026-10-12: 실제 경험의 시기를 "지난해"로 잘못 적은 오류가 여러
  지원서에 번졌다 — 상대 표현은 작성 시점에 틀리기 쉽고, 해가 바뀌면 맞던 문장도 틀려진다)

### Step 9. 출력 형식

```text
---
[문항]

[작성된 문단]

참조한 경험: [경험명] ([파일명])
참조한 기업 정보: companies/[기업명].md (없으면 생략)
참조한 레퍼런스: [파일명 또는 "MCP 검색 결과"] (없으면 생략)
글자수: [N]자 (띄어쓰기 포함/제외)
---
```

### Step 10. output 저장

작성 완료 후 `outputs/[이름]/[기업명]_[직무명].md` 에 저장한다

저장 형식:

```text
# [기업명] [직무명]

## [문항 전문]
글자수: [N]자 (띄어쓰기 포함/제외)

[작성된 문단]

---
참조한 경험: [경험명]
작성일: YYYY.MM.DD
```

- 같은 파일이 이미 있으면 새 문항을 하단에 추가(append)한다
- 기업명과 직무명은 사용자가 말한 것 그대로 사용한다 (예: BGF리테일_영업관리.md)

### Step 11. 사용자 최종 편집본 학습 (고도화 2026-09-28)

사용자가 이 스킬로 작성한 초안을 직접 고친 "최종본"을 다시 보여주면, 사실관계(경험 DB에 새로
드러난 정보)만 확인하고 끝내지 않는다. 직전 초안과 최종본을 문장 단위로 대조해서 **문체가
바뀐 지점**을 찾는다 (주어 생략 여부, 메타/예고성 문장 삭제, 절 개수, 명사 반복, 수치를
어디에 쓰고 어디서 뺐는지, 마무리 포부의 범위 등). 우연한 다듬기가 아니라 반복 가능한
패턴으로 보이면 `users/[이름]/writing-style.md`에 날짜와 근거 예문을 붙여 추가하고, 다음
작성부터 바로 적용한다.

## 절대 금지

- 경험을 지어내거나 과장하지 말 것
- `writing-style.md` 와 다른 어투 사용 금지
- 글자수 초과 금지
- bullet point 형식 사용 금지
- 활동을 3개 이상 나열하는 것 금지
- 합격 사례 레퍼런스의 문장을 그대로 쓰는 것 금지
