# Skill: write-resume

## 목적

지원 공고의 필수조건 순서에 맞춰 사용자의 경험을 재배치한 이력서를 만든다.
자소서와 달리 **새 문장을 창작하지 않는다** — 이미 있는 profile.md, experiences/*.md
내용을 조건 순서에 맞춰 고르고 재배열하는 작업이다.

## 트리거

"[이름] [기업명] [직무명] 이력서 써줘"

> 이미 이 공고를 매칭한 적이 있다면(ROADMAP S5-1, `matches` 테이블에 행이 있다면), 이
> 스킬을 대화로 처음부터 실행할 필요 없이 `lib/resume.py` 의 `generate_resume()` 가 그
> 매칭 결과(조건별 근거 경험)를 그대로 재사용해 코드로 재배치한다 — 새로 판단할 게 없기
> 때문이다(1-B, S3-1 의 lib/selector.py 와 같은 이유: 이미 구조화된 데이터가 있으면
> LLM 을 다시 부르지 않는다). 아래 절차는 매칭 기록이 없어 대화로 처음부터 판단해야 할
> 때 쓴다.

## 절대 원칙

1. **창작이 아니라 재배치다.** 경험 파일의 활동 내용/성과를 새로 쓰지 않는다. 문장을
   다듬더라도 없는 사실을 추가하지 않는다.
2. **근거 없이 조건에 대응시키지 않는다.** 조건에 대응하는 경험을 배치했으면, 그 경험이
   실제로 그 조건을 뒷받침하는 내용을 담고 있어야 한다(ROADMAP 1-C 와 같은 원칙).
3. 공고의 필수조건 순서를 그대로 따른다 — 사용자의 경험 DB 순서(파일명, 날짜)가 아니다.
4. 조건에 대응하지 않는 경험은 지어내서 끼워 맞추지 말고 "기타 경험"에 참고용으로만 둔다.

## 실행 순서

### 1. 공고 필수조건과 경험 대조

skills/match-jobs.md 의 1~2단계와 동일하게, 필수조건 각각에 가장 잘 대응하는 경험 파일
하나씩을 고른다(근거가 약하면 배치하지 않는다).

### 2. 순서 결정

필수조건이 나열된 순서대로 대응 경험을 배치한다. 하나의 경험이 여러 조건에 대응하면
처음 등장하는 조건 위치에 한 번만 놓고, 나머지 조건에는 "위 항목 참고"로 표시한다.

### 3. 이력서 작성

templates/resume-entry.md 형식을 그대로 따른다(원문을 프롬프트에 첨부받아 그 구조를
정확히 따를 것 — 형식을 말로만 설명받으면 임의 구조를 만들어낸다는 것이 이 프로젝트에서
반복 확인된 문제다). "핵심 성과"는 경험 파일의 Result 섹션에서 발췌하되 새로 쓰지 않는다.

### 4. 완료 보고

몇 개 경험이 몇 개 조건에 배치됐는지, 대응하지 못한 조건이 있는지 보고한다.

## 절대 금지

- 경험 내용을 새로 창작하거나 과장하는 것
- 근거 없이 조건에 경험을 끼워 맞추는 것
- 공고 필수조건 순서를 무시하고 임의 순서로 배치하는 것
- raw/ 파일을 수정하거나 삭제하는 것
