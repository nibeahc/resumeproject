# Skill: match-jobs

## 목적

공고의 필수조건/우대조건을 사용자의 경험 DB(experiences/*.md)와 조건 단위로 대조해
충족 여부와 근거 경험을 매긴다. 자소서 작성 전에 "이 공고에 지원할 만한가"를 판단하는
근거를 만드는 단계다.

## 트리거

"[이름] [기업명] 매칭해줘" 또는 웹 라우트가 조건 배열과 경험 전문을 넘겨 호출

## 절대 원칙 (ROADMAP 1-C)

1. **근거 경험 없이 "충족"으로 판정하지 않는다.** 조건을 만족한다고 판단했으면 반드시 그
   근거가 되는 실재하는 경험 파일명을 함께 낸다. 근거를 댈 수 없으면 "충족"이 아니라
   "부분충족" 또는 "미충족"으로 낮춘다.
2. **경험 파일명을 지어내지 않는다.** 반드시 실제로 주어진 경험 목록에 있는 파일명만
   인용한다 (코드가 사후에 실재 여부를 검증하며, 존재하지 않는 파일명을 인용한 판정은
   자동으로 "미충족"으로 강등된다 — 처음부터 정확히 낼 것).
3. **조건에 없는 내용을 판정 근거로 쓰지 않는다.** 경험이 조건과 관련 있어 보여도, 조건이
   요구하는 구체적 내용(예: 연차, 기술 스택, 자격증)이 경험 본문에 실제로 있는지 확인한다.
4. 애매하면 "부분충족"을 쓴다. "충족"은 조건을 명확히 만족하는 근거가 있을 때만, "미충족"은
   관련 경험이 전혀 없을 때만 쓴다.

## 실행 순서

### 1. 조건별 대조

필수조건과 우대조건 각 항목에 대해, 주어진 경험 전문을 모두 살펴보고 판단한다.

- **충족**: 조건이 요구하는 내용을 경험이 구체적으로 뒷받침한다 (근거 경험 파일명 필수)
- **부분충족**: 관련은 있지만 조건을 완전히 충족한다고 보기는 어렵다 (예: 조건은 "3년 이상"인데
  경험 기간이 그보다 짧음, 또는 유사 기술이지만 정확히 같은 기술은 아님) — 근거 경험 파일명 필수
- **미충족**: 관련 경험이 전혀 없다 — 근거 경험 파일명 없음(null)

하나의 조건에 여러 경험이 걸치면 가장 강하게 뒷받침하는 경험 하나만 근거로 든다.

### 2. 미충족 조건에 보완 가능 여부 메모

미충족 또는 부분충족 조건에는 `note` 에 한 줄로 보완 가능 여부를 적는다
(예: "다른 프로젝트 경험을 추가로 서술하면 보완 가능", "자격증은 지금 당장 보완 불가").

### 3. 출력

아래 형식으로 정확히 출력한다. 다른 설명은 블록 밖에 쓰지 않는다. 배열의 순서와 개수는
입력받은 필수조건 배열 다음 우대조건 배열 순서와 정확히 같아야 한다 (조건을 빼거나 더하지
않는다).

```text
===EVIDENCE_JSON===
[
  {"condition": "조건 원문", "kind": "필수", "verdict": "충족", "evidence_file": "2022-예시.md", "note": ""},
  {"condition": "조건 원문", "kind": "우대", "verdict": "미충족", "evidence_file": null, "note": "관련 경험 없음, 보완 어려움"}
]
===END===
```

### 4. 관심직무.md 역방향 갱신 제안 (ROADMAP S5-3, 대화형 실행 시에만)

> 웹 경로(web/routes/matches.py)는 공고 하나씩 조건 대조(1~3단계)만 코드로 자동 호출한다.
> 여러 공고를 한 번에 보지 않고, 파일을 쓸 권한도 없으므로 이 단계는 수행하지 않는다.
> 대화형으로 이 스킬을 직접 실행할 때(예: "[이름] 매칭해줘", 또는 이미 매칭된 여러 공고
> 결과를 사용자가 함께 보여달라고 했을 때)만 이 단계를 수행한다.

여러 공고를 매칭했다면, 그 공고들의 필수조건/우대조건 원문을 훑어보고
`users/[이름]/관심직무.md` 의 해당 직무 "핵심 키워드"에 없는데 **서로 다른 공고 2건
이상**에서 반복 등장한 요구사항이 있는지 확인한다. 있으면 추가를 **제안**만 한다.

**판단 기준**:
- 같은 취지의 요구사항(동의어 포함, 예: "SQL 능숙" 과 "SQL 활용 가능")이 서로 다른 공고
  2건 이상의 필수 또는 우대조건에 등장했는가
- 그 키워드가 관심직무.md 의 핵심 키워드/추천 표현에 이미 있는가 — 있으면 제안하지 않는다
- 사용자의 경험 DB 충족 여부와는 무관하다. 이건 "이 직무 시장이 실제로 요구하는 것"을
  관심직무.md 에 반영하자는 제안이지, 사용자가 이미 갖췄는지와는 별개다

**제안 형식** (대화 응답에 자연스럽게 포함, 별도 구분자 블록 없음):

```text
관심직무.md 갱신 제안 — [직무명]

최근 매칭한 공고에서 아래 요구사항이 반복 등장했지만 관심직무.md 핵심 키워드에는
없습니다:
- [키워드/표현] (등장 공고: [기업명1], [기업명2])

관심직무.md 에 추가할까요? (예 / 아니오 / 직접 수정)
```

사용자가 승인하면 그때만 관심직무.md 를 수정한다. "예"를 받기 전에는 파일에 손대지 않는다.

## 절대 금지

- 근거 경험 파일명 없이 "충족" 또는 "부분충족" 판정하는 것
- 주어지지 않은 파일명을 근거로 지어내는 것
- 조건을 빠뜨리거나 순서를 바꾸는 것
- 관심직무.md 나 배경지식으로 조건을 임의로 완화·해석하는 것
- 사용자 승인 없이 관심직무.md 를 직접 수정하는 것 (Step 4는 제안까지만, 승인 후에만 반영)
- 서로 다른 공고 2건 미만에서만 등장한 요구사항을 "반복 등장"이라고 부풀려 제안하는 것
