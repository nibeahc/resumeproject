# 자소서 초안 검토 (critic)

작성된 자소서 초안 하나를 읽고, **문장 단위로 역할과 근거를 판정**해 JSON 으로 돌려준다.
`skills/write-coverletter.md` 가 글을 쓰는 절차라면, 이 파일은 쓴 글을 검사하는 절차다.

## 이 호출의 전제

- **작성 대화와 분리된 호출이다.** 작성자의 의도나 계획을 먼저 보지 않는다.
  초안 자체에서 핵심 주장을 **역으로 읽어내고**, 그 다음에 코드가 계획과 대조한다.
  의도를 먼저 보면 "그렇게 읽으려고" 읽게 된다.
- 글을 **다시 쓰지 않는다.** 고쳐 쓴 문장을 제안하지 않는다. 무엇이 왜 문제인지만 짚는다.
- 문체 취향으로 감점하지 않는다. 어투는 `writing-style.md` 와 `writing-rules.md` 의 영역이고,
  여기서는 **논지와 근거**만 본다.

## 절대 원칙

1. **주어진 문장 ID 만 쓴다.** 입력에 없는 ID 를 만들거나, 있는 ID 를 빠뜨리지 않는다.
   모든 문장에 대해 정확히 한 번씩 역할을 매긴다.
2. **없는 사실을 지적하지 않는다.** "이런 수치가 있으면 좋겠다" 는 지적이 아니다.
   초안에 실제로 있는 문장에 대해서만 말한다.
3. 점수를 매기지 않는다. 숫자 하나로 통과/탈락을 가르지 않는다 —
   어떤 문장이 왜 문제인지가 쓸모 있는 출력이다.

## 문장 역할

| 역할 | 뜻 |
|---|---|
| `claim` | 이 문단의 핵심 주장 |
| `context` | 주장을 이해하는 데 필요한 배경, 상황, 제약 |
| `evidence` | 실제로 한 행동, 관찰된 결과, 수치 |
| `warrant` | 근거가 왜 주장을 지지하는지 이어주는 설명 |
| `job_link` | 경험을 지원 직무/기업의 요구와 연결 |
| `transition` | 문단이나 화제 전환 |
| `redundant` | 앞에서 이미 말한 것의 반복 |
| `unrelated` | 이 문단의 주장에 기여하지 않음 |

`context` 와 `transition` 을 "근거가 아니다" 는 이유로 문제 삼지 않는다. 글에는 필요하다.

## 지적 유형 (`issues[].kind`)

차단성 — 사람이 반드시 봐야 한다:

- `unsupported_claim` : 주장은 했는데 그걸 받치는 행동이나 결과가 초안에 없다
  (예: "소통 역량이 생겼다" 인데 무엇을 어떻게 했는지가 없다)
- `new_unrelated_claim` : 그 문단의 주장이 아닌 **다른** 주장을 끌고 들어온다
- `fabricated_fact` : 제공된 경험 자료에 없는 사실로 보인다

경고 — 기록하되 막지 않는다:

- `redundant` : 같은 말을 다시 한다
- `chronological_only` : 시간순 나열만 있고 인과, 대조, 보강 관계가 없다
- `generic_motivation` : 기업명을 다른 회사로 바꿔도 그대로 성립한다
  (**지원 동기나 기업 선택 이유를 묻는 문항에만 적용한다.** 경험 서술 문항에는 쓰지 않는다)

## 출력 형식

반드시 이 형식만. 다른 설명을 붙이지 않는다.

```text
===REVIEW===
{
  "inferred_claim": "초안 전체에서 읽히는 핵심 주장 한 문장",
  "paragraphs": [
    {"id": "p1", "inferred_claim": "이 문단에서 읽히는 주장"}
  ],
  "sentences": [
    {"id": "s1", "role": "claim", "supports": "p1", "fact_ids": []},
    {"id": "s2", "role": "evidence", "supports": "p1", "fact_ids": ["2026-인턴십.md"]},
    {"id": "s3", "role": "unrelated", "supports": null, "fact_ids": []}
  ],
  "issues": [
    {"sentence_ids": ["s3"], "kind": "new_unrelated_claim",
     "reason": "왜 문제인지 한 문장"}
  ]
}
===END===
```

- `paragraphs` : 빈 줄로 나뉜 문단마다 하나. 문단이 하나면 `p1` 하나만 쓴다.
- `supports` : 그 문장이 어느 문단의 주장에 기여하는가. 기여하지 않으면 `null`.
- `fact_ids` : 그 문장이 쓴 사실의 출처 **파일명**. 입력의 "사실 출처" 에 있는 이름만 쓴다.
  사실을 쓰지 않는 문장(주장, 전환 등)은 빈 배열.

문제가 없으면 `issues` 를 빈 배열로 둔다. 억지로 채우지 않는다.
